# Базовые принципы именования end-point`ов

- использовать существительные во множественном числе
```
правильно /users /products
неправильно /get_users /create_products
```
- использовать вложенность (иерархию) для связи ресурсов
```
пример: /users /{userId} /orders
```
- использовать кебабкейс kebabCase
```
пример: /items /{itemId} /upload
```
- избегать лишних слов (недобавлять глаголов если это не требуется)
```
пример правильно: /products
пример неправильно: /get_products
```

# Как выбрать http метод
- создать => post => создает новый ресурс 
```
пример: 
    POST/products
    POST/users/{userId}/upload
```
- получить => get => возвращает данные не изменяя ресурсы
```
пример:
    GET/users
    GET/users/{userId}/profile
    GET/users?id=7
```
- обновить (изменить)=> put или patch => обновляет существующий ресурс 
```
put полная замена ()
    пример: PUT/users/{userId}/avatar (обновление аватара)
patch частичная замена
    пример: PATCH/users/{userId}/settings
```
-удалить => delete => удаляет ресурс или помечаеть его как удаленный по id
```
пример:
    Delete/users?id=2
    Delete/users/{userId} (предпочтительнее)
```

# Когда использовать qerry-параметры
qerry-параметры -это параметры после ? в url
- необходимо фильтровать сортировать или искать по данным
```
    GET/products?filters={status:"ordered"}
    GET/products?sortKey=1
```
- погинация(page и limit)
```
    GET/products?name=ASC
    GET/products?order={name:"ASC";price"DESC"}
```
- передача данных которые не являются частью индификатора ресурса
```
    GET/search?q=Android
    GET/products?page=1,2 limit=20
```

# Когда использовать path-параметры - это часть url в {} обычно туда помещаются id или uuId
```
    PATCH/users/{userId}/settings
                    |
              Patch-параметр
```
- когда нужно указать объязательный id ресурса
- обращение к конкретному экземпляру рксурсов
- реализация иерархического url-запроса
```
    GET/users/{usersId}/orders?status=Completed
```

# Когда используется Body 
- в методах POST PUT PATCH 
- Body - это строковое представление json объекта
```
POST/users
Body:<          
    name:
    lastname:
    age:27>

PATCH/users/{userId}/settings
Body:<
    is active:true>
```

# Правило формирования ответа
- при формировании ответов на сервере сначала проверяетс на доступность запрашиваемые данные 
- проверка на существование сопутствующих сущностей 
- формирование структуры ответа на основе существующих сущностей в бд 
- когда сущность пополняется данными в результате запроса в ответе должна быть информация только о созданной сущности
- В случаии если пользователю не нужны обновленные данные из бд поскольку он сам их изменил то ответ мжет быть пустым (обычно со статусом кода 200/204)
```
[{userId;rooms:[{last_message}]}]
```
```
GET /users/{userId}/history
```
